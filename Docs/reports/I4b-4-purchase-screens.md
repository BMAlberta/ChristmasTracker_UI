## Decisions taken in this story
- Screen name `ManagePurchaseView` (distinct from the legacy `PurchaseDetailView`, which Story D deletes). The model is built once in a `.task` guarded by `model == nil` (the environment's purchase service cannot be read in an init); the cost is one frame of a "Loading purchase..." progress view.
- A `.notFound` from a shipping or notes save closes the screen as gone with no banner (the purchase no longer exists). Accepted by the acceptance reviewer; unsaved edits are dropped silently. Covered by the two tests added after Gate 2.
- `load()` returns early if already loaded, so a repeated `.task` cannot wipe unsaved edits.
- `ItemDetailView.onDisappear` skips clearing the item detail while a purchase is open (otherwise pushing the purchase screen would clear `currentItem`). The reviewer traced teardown: `ItemService.clearForSession` still clears it at logout.
- Section subviews live in ManagePurchaseView.swift because the scan tests require many tokens in that file.
