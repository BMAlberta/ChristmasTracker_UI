# I3c-1: The archived-lists tab (Story A)

Branch: feat/i3c-items. Path: full pipeline (listing and session layer). Decision basis: the brief's archived-lists decision ("L16" as cited by the brief; see Deviations D2: L16 is not in the synced docs).

## What changed
- Lists screen (DashboardView): an Active | Archived segmented `Picker` (default Active), per-segment empty states from the pure `ListSegmentState` ("No active lists", "No archived lists", "No Results" when searching), search applied before the segment, an "Archived" badge on archived rows, and the swipe action is now "Archive" (only when `showsDeleteAction`, i.e. `canDeleteList`).
- List detail (ListDetailView): "Archive List" button replaces "Delete List"; the Archived badge in the header; a 422 stays on the screen with the plain message.
- ListService: `lists` keeps every non-removed list; `activeLists` (ACTIVE, DRAFT) and `archivedLists` (ARCHIVED) are derived; `deleteList` = archive: records no removal, then fetches `GET /lists` directly from the repository (not the cache, not `refreshLists`), writes lists and cache from the response (no local status synthesis), and refetches the open detail. Stale loads are discarded by an archive epoch (global for list loads, per list id for detail loads); overlapping archives are ordered by a reload token; `isMutating` is a counter. 422 `CANNOT_EDIT_ARCHIVED_LIST` (`archivedReadOnly`) no longer drops the list or sets `goneListId`: the detail is refetched so the flags refresh and the typed error is still thrown. `notFound` and forbidden-with-cache still mean gone.
- ViewState: `ListSegment`, `ListSegmentState`, `ListArchiveConfirmation` (replaces `ListDeleteConfirmation`, deleted), `ListArchivedBadge`, `ListArchiveCompletion`, `isArchived`/`showsArchivedBadge` on the row and detail states; `ListErrorPresentation(.archivedReadOnly).shouldLeaveScreen == false`.
- MockListRepository: `deleteList` archives (four management flags false, item flags and `canLeaveList` unchanged); `updateList`/`removeCoOwner` on an archived list throw `archivedReadOnly`. ListDataStore: `setListDetail` updates the summary for any status. ListRespository: the `archivedReadOnly` message is now "This list is archived and can't be edited."
