# CLAUDE.md — Christmas Tracker iOS

## Role
The main session is the Orchestrator. Plan, write a short Gate 1 spec, route work to the
subagents in .claude/agents (test-writer, implementer, convention-reviewer,
acceptance-reviewer), and hold both gates. Do not write production code or tests yourself
during a story.

## Read from disk every session (authoritative; never from memory or project search)
- contract/openapi.json (generated by the backend; never hand-edit)
- Docs/DECISIONS.md (highest revision), Docs/PRD.md, Docs/client-guide.md, Docs/error-codes.md
- Docs/epics/<current>.md (the brief for the current package)
- Docs/process/coding-standards.md, Docs/process/testing-conventions.md
- Docs/ios-state-audit.md
- Base branch is master (the rewrite was promoted onto it; the 4.4 release is the tag 4.4
  and the branch legacy/4.4). Before branching run git branch --show-current. Branch
  feat/<slug> or fix/<slug> from master; open PRs with gh pr create --base master. Never
  push to master or main directly.

## Contract and privacy rules
- If the server disagrees with the contract or the docs, do not work around it. Add a row
  to Docs/contract-issues.md (what the contract says, what happened, request and response,
  client "ios") and stop that item.
- API models come from the generated client and are mapped to domain models at the
  repository boundary. Never hand-write API models.
- UI visibility comes from the capability flags on list responses (isRecipient,
  canSeeGiftActivity, canPurchase, canAddOffList, canSeeOffList, canCreateItem), never from
  roles. Blind viewers and viewers never see counts, statuses, or off-list items. A 404
  means "not found", never "forbidden".

## Pipeline (relaxed: family scale, ship fast)
- Gate 1 (short): contract slice, acceptance criteria, scoped file or folder list, and
  whether a new interface is introduced.
- Weight: solo by default (one implementer writes failing tests, implements, loops
  build and test). Full pipeline (isolated test-writer and implementer, both reviewers)
  only for: auth, session, refresh, Keychain, biometrics; capability-flag-driven UI;
  purchase and budget confirmation; the generated-client and repository layer.
- Gate 2: convention-reviewer on every story; acceptance-reviewer on the full path.
- Rejection routing, the stuck detector (3 attempts; a repeated error signature stops),
  and the scope-creep halt are defined in the agent files. Honor them.

## Behavior gates
- Verify the default branch (main) before branching. Branches: feat/<slug>, fix/<slug>.
  Plain -m commits, one commit per story. Never push; the human pushes.
- Run scripts/verify.sh before reporting done and paste its raw summary.
- Report each story in Docs/reports/<package>-<story>.md: what changed, commands and raw
  output, deviations, and "Not done or partial". Never write None unless it is true.

## Standing requirements
- Swift 6 strict concurrency; @Observable, async/await, actors; no Combine; no GCD; no
  force unwraps in new code.
- @Instrumented on new or modified async/throws functions in repository, service, and
  view-model layers (never retrofitted). Actor-isolated methods use manual Sentry
  instrumentation with an explaining comment.
- Services through the environment; protocols use the -ing suffix. Use the
  swiftui-expert-skill for SwiftUI work. Follow Theme tokens if the audit found them.

## Command habits
One command at a time from the repo root. Quote every path (the Xcode project is in
ChristmasTracker/). No git -C, cd, &&, ;, or echo. Pipes only to head, tail, or grep. Use
scripts/build.sh, scripts/test.sh, and scripts/verify.sh. Never run xcodebuild archive or
export, or xcrun simctl erase. No Workflow tool or parallel subagents for edits.
